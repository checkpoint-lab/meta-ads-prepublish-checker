# Meta広告 公開前チェッカー v0

Meta広告マネージャで、公開前に自動調整系の設定がOFFになっているかを確認する、Chrome拡張の試作版です。非公式で、Meta社とは関係がありません。無料です。

## 何をするか

広告作成画面の左下にある「公開前チェック」ボタンを押すと、画面のスイッチ（トグル、チェックボックス）を読み取り、次の6項目がONになっていないかを一覧にします。ボタンは、「公開する」ボタンとの押し間違いを避けるため、左下（左メニューの右側）に置いています。

| 項目 | 見ているもの |
|---|---|
| クリエイティブ翻訳 | 「翻訳」を含むスイッチ。ラベルが「言語」だけのスイッチ（広告の自動翻訳の設定）も含む |
| 柔軟性のあるメディア | 「柔軟性のあるメディア」「フレキシブル」（私の確認では、現在の画面に該当スイッチが見つかっていません） |
| 複数広告主の広告 | 「複数広告主」「複数の広告主」、英語の multi-advertiser、multiple advertisers |
| 基本的なエンハンス | 関連度が高いコメント、明るさとコントラスト、スポットライト |
| Advantage+ クリエイティブ エンハンス | タッチアップ、テキストの改善、オーバーレイ、アニメーション、音楽、3D、ビデオ効果、画像テンプレート、トリミングと拡大、画像の拡張、CTAエンハンス（英語表記も） |
| その他の自動追加 | ラベルに「サイトリンク」を含むスイッチ（自動追加かどうかは区別しません）、「ブランディングを適用」「ウェブサイトのハイライト」 |

パネルの一番上には、全体の判定を3段階で出します。赤の「NGがあります」、橙の「確認が完了していません」（未検出や状態不明の項目が残っている）、緑の「すべての項目がOFFです」です。

項目ごとの結果は NG（ONのものがある）、OK（見つかったものがすべてOFF）、未検出（該当スイッチが見つからない）、状態不明（ON/OFFを読めないものがある）で表示します。

どの項目にも当てはまらないスイッチは、「判定対象外」として、ラベルとON/OFFを一覧に出します。上の6項目に入っていない自動調整系の設定が、ここに出ることがあります。チェック対象の項目は、パネル内で外せます。結果をテキストでコピーするボタンもあります。

## 使い方の注意

Metaの画面は、見えている範囲のスイッチしか描画しないことがあります。このため、次の3つの方法で読み取りを補っています。

1. **設定のまとめ文を読む。** 広告の編集画面には、「Advantage+ クリエイティブエンハンス (4/5件)　オフ: …　オン: …」「基本的なエンハンス (2/4件)」「クリエイティブの設定 (0/3件)　オフ: ブランディング、サイトリンク、ウェブサイトのハイライト」のようなまとめ文があります。ここに表示されていれば、スイッチを1つずつ見なくても、ONの項目名と件数を読めます（括弧内は「ONの件数/全体の件数」）。「他1件」のように名前が省略されている分と、名前を読み取れた件数が括弧内より少ないときの差は、「名称不明」のONとして数えます（件数は最大50件まで）
2. **パネルを開いている間は、スクロールして表示されたスイッチも合算する。** 画面の変化を検知して、読み取りを繰り返します
3. **広告ごとに記憶する。** 広告の識別子ごとに、読み取った結果をブラウザ内（`chrome.storage.local`）に保存します。保存するのは、各スイッチのラベル（タイトル120字、全文200字、周囲300字まで）、ON/OFF、判定項目で、1広告あたり80件まで、最新の30広告までです。広告の識別子は、広告編集画面のURLにある `selected_ad_ids`（64字まで）です。これがない画面では、広告アカウントのIDと画面のパスを、それぞれ64字までにして連結したものを使います。ページを読み直しても、前回の結果が残ります。前回の結果は、画面の再読み取りで上書きされるまで「記憶」として扱い、記憶を含むOKには注記が付きます

- 広告のクリエイティブ設定は、ステップごとに画面が変わります。まとめ文に出ない項目は、各ステップで、パネルを開いたままスクロールしてください
- 記憶には、すでに存在しない設定が、NGのまま残ることがあります。「記憶をリセット」で、その広告の保存済みの確認結果を、現在の画面の読み取り結果で置き換えます。保存した内容をすべて消すには、拡張機能を削除してください
- 記憶は、まとめ文または画面のスイッチで再確認されるまで、古い可能性があります。公開前には、必ず、画面を読み直してください

## 何をしないか

- 設定を書き換えません。クリックもしません。読み取るだけです
- 通信しません。画面の内容を外部に送りません。保存するのは、チェック対象の選択と、広告ごとの記憶（上の「使い方の注意」を参照）です。保存先はブラウザ内の `chrome.storage.local` だけです
- ボタンでパネルを開いたときだけ読み取ります。パネルを開いている間は、画面の変化を検知して、読み取りを繰り返します
- 配置別アセットの割り当てや、公開後の配信内訳の確認はできません

## インストール（開発者モード）

1. このフォルダをZIPから展開します。
2. Chromeで `chrome://extensions` を開き、右上の「デベロッパーモード」をONにします。
3. 「パッケージ化されていない拡張機能を読み込む」を押し、`extension` フォルダを選びます。
4. 広告マネージャ（`adsmanager.facebook.com` または `business.facebook.com`）を開くと、左下にボタンが出ます。
5. 拡張を更新したときは、`chrome://extensions` で再読み込みして、広告マネージャのタブを更新してください。

## 検証状況

**本物の広告マネージャでの確認（2026年10月6日、Chrome、日本語の画面、1つの広告アカウントで下書きを作成。公開はしていません）**

- 確認できたもの：
  - 拡張の読み込みと、ボタン・パネルの表示
  - スイッチの検出と、ON/OFFの読み取り（トグルとチェックボックス）
  - 「複数広告主の広告」にチェックが入っている状態を、NGと判定
  - 「音楽を追加」（Metaが「デフォルトでオン」と表示）を、NGと判定。画面のスイッチの状態と一致
  - ページを開いた直後（スクロールなし）に、広告の編集画面の「設定のまとめ文」を読み取り、「Advantage+ クリエイティブエンハンス ON 4/5件」「基本的なエンハンス ON 2/4件」を検出。「関連度が高いコメント」「CTAエンハンス」がONであることを、NGとして表示
  - 広告IDを、URLの `selected_ad_ids` と一致する値で取得
  - 失敗例：スイッチだけを読む旧版は、画面に見えていた「基本的なエンハンス」の2件がOFFであることから、OKと表示しました。しかし、まとめ文では、見えていない2件がONでした。見えた範囲だけでOKと言うことは、この種のツールで最も危険な誤りです。現在の版でも、同じ状況は起こりえます。まとめ文が画面にあるときは、見えていない項目も含めて判定できるので防げますが、まとめ文が画面にないときに、項目の一部のスイッチだけが見えていてすべてOFFなら、その項目はOKと表示されます。この場合、全体判定の緑のバナーも出ることがあります。公開前に、未検出の項目と、まとめ文が見つかっているかを、必ず確認してください
  - スイッチ自体の `aria-label` が「オン/オフ」のような状態の文言だった問題を、修正前の版で確認し、修正後の版で解消を確認
  - 広告ごとの記憶の保存と、ページを読み直したあとの復元：パネルに「前回の確認：（日時）」が表示された
  - 全体判定のバナーのうち、赤（NGがあります）と橙（確認が完了していません）
  - パネルを開いたまま、画面を下までスクロールすると、通過したスイッチ（複数広告主の広告）が、ページの先頭に戻っても、判定に残る
  - 新しい形式のまとめ文「クリエイティブの設定 (0/3件)　オフ: ブランディング、サイトリンク、ウェブサイトのハイライト」を読み取り、「その他の自動追加」をOKと判定
  - ラベルが「言語」だけのスイッチ（広告の自動翻訳の設定、OFF）を、クリエイティブ翻訳として判定し、OKと表示
  - 結果のコピー：「結果をコピー」を押して、メモ帳に貼り付けられた（貼り付けた文章を、確認者が提供してくれた）
  - チェック対象の選択の保存：「チェック対象」の1つを外して、ページを読み直しても、外れたままだった（文章での報告）
  - 失敗例：周囲の文字で分類する処理が、「広告プレビュー」のスイッチを、近くの「埋め込みオーバーレイ」の文字に引きずられて、「Advantage+ クリエイティブ エンハンス」に誤分類し、ONの件数を5/6件と表示しました。周囲の文字を分類に使うのをやめて修正しました（修正後の版の実機確認は、まだです）
- 確認できていないもの：
  - 「柔軟性のあるメディア」：現在の画面に、このラベルのスイッチが見つかっていません。メディア欄が配置ごとに分かれた構成に変わっており、名前の変更か、場所の違いが考えられます
  - 全体判定の緑のバナー（すべての項目がOFFのとき）：NGや未検出が残らない状態を、実機で作れていません
  - 別の広告アカウント、英語の画面、Chrome以外のブラウザ

**自動テスト**

- 判定ロジックの単体テスト74項目は、すべて通ります（`node test/run-rules-test.cjs`）
- ブラウザ上のモック画面（`test/mock-adsmanager.html`）で、ON/OFFの判定、非表示領域の除外、ラベルを特定できないスイッチの件数表示、判定対象外の一覧、状態不明の表示、状態の文言をラベルと取り違えないこと、説明文が別の要素にあるスイッチの判定、画面から消えたスイッチの記憶を確認しました

## 既知の制限

- Metaの画面は頻繁に変わります。変更で検出できなくなった場合は「未検出」になるので、目視で確認してください
- 日本語と英語のラベルだけを想定しています
- ラベルは、タイトル、説明文を含む全文の順に照合します。タイトルがどの項目にも当てはまらず、説明文に別項目の語があると、別の項目として数えることがあります。スイッチの周囲の文字は、分類に使いません（実機で、広告プレビューが、近くの「埋め込みオーバーレイ」の文字に引きずられて、誤分類されたため）
- タイトルの判定は、スイッチを含む要素の文字が、タイトルと説明で改行されて表示される構造を前提にしています
- 想定していない言い回しは、「判定対象外」か「未検出」になります。実機では、キャンペーン一覧の「すべての広告を選択」のチェックボックスのような、自動調整ではない設定も、判定対象外に出ます
- 「ラベルを特定できなかったスイッチ」は判定に含まれません
- 全体判定のうち、実機で確認したのは、赤と、橙（未検出が残るとOKにならない）です。緑の表示は、実機でも、モック画面の記録でも、確認していません。チェック対象がゼロのときの橙は、モック画面で確認しました
- 広告ごとの記憶は、すべての広告を1つの保存領域にまとめて保存します。複数のタブで、別々の広告を同時に開くと、片方の記録が失われることがあります。また、1広告あたり80件を超えるスイッチがあるときは、項目に分類できないスイッチから先に、保存から落とします
- 画面に描画されないスイッチは、スクロールして表示するまで読み取れません。実機では、ページを開いた直後に読めたのは、設定のまとめ文だけでした。「クリエイティブ翻訳」「複数広告主の広告」などは、パネルを開いたまま、その設定が見える位置までスクロールする必要があります。一度表示された項目は、パネルを開いている間と、同じ広告に戻ったときに、記憶から判定されます
- パネルの上部の全体判定は、未検出や状態不明が残る間は、OKになりません。公開前に、未検出の項目を、画面で確認してください
